# strategy-audit

审查**回测到净值这一段有没有偷分**。

不告诉你策略好不好 —— 告诉你这份净值能支撑什么结论。

```bash
pip install strategy-audit
strategy-audit --weights w.csv --prices panel.csv
```

```python
from strategy_audit import audit_strategy

rep = audit_strategy(weights, prices)   # 权重面板 + 价格面板
print(rep.text())
```

---

## 它查什么

回测出净值这一步有一批**静默缺陷**：净值曲线照样漂亮，错误却不体现在任何一个
你会去看的数字上。本工具查两族。

### 族一：换手与成本真实性

| 检查 | 抓的是 |
|---|---|
| 换手口径 | 朴素 `0.5·Σ\|Δw\|` vs 漂移调整口径 |
| 反推换手 | 用持仓自相关反推换手，与实测的比值 |
| 盈亏平衡成本 | 多大的单边成本会把超额吃到 0 |
| 毛净对账 | 由毛净两条曲线反推你**实际**扣了多少 bp |

### 族二：前视与记账

| 检查 | 抓的是 |
|---|---|
| 调仓日对齐 | 用 t 日收盘定权重，却把 t 日涨幅也算进去 |
| 权重前视 | 权重与**同期**收益相关（市值加权用期末市值最典型） |
| 股票池生存者 | 持仓只落在「活到末日」的标的上 |
| 成分变动记账 | 缺价标的的三种政策给出净值区间 |

前视排在成本**之前**跑：前者问「这份净值是不是真的」，后者问「扣够了没有」。
前者不成立时后者没有意义。

## 四个会静默算错的地方（合成面板）

下面的数字都由本仓库的合成面板测出，`tests/` 里可复现。它们是**机制演示**，
不是对你的数据的预测 —— 你的量级取决于你的组合。

### 1. 「什么都没改」不等于「不用交易」

目标权重恒定（10 只等权，从不调整）时：

```
朴素 0.5·Σ|Δw|  =  0.00% /期
漂移调整         =  2.59% /期
```

朴素口径报 0 换手。但价格漂移会让实际持仓偏离等权，拉回目标就是一笔真实交易。
按朴素口径算成本，这部分**完全不收费**。

反过来，权重真的在动时朴素口径**高估** —— 它把「价格涨了导致权重变大」也算成
一笔交易，而那笔交易并不存在。两个偏差方向相反，不能互相抵消着蒙。

### 2. 反推换手的偏差方向不固定

```
由持仓自相关反推  89.0% /期
按实际权重实测    78.6% /期      比值 1.13
```

这里是**高估** 13%。但用全池信号自相关反推时我实测过**低估** 2.6 倍
（推 1.98x / 实际 4.6x）。偏差方向随反推用的是哪个量、组合有多少持仓、
是否等权而变 —— 所以不能靠经验修正，只能按实际权重变化算。

工具报你这份数据上的实测比值，不预设方向。

### 3. 成分变动 ≠ 退市

含 6 只中途退市标的（退市前 20 日跌 80%）的面板上，同一组权重、三种记账政策：

```
无损移除（drop）        +30.68%
持有最后价（hold_last） +22.36%
全额清算（zero）         +0.05%     跨度 30.63pp
```

只有 2 期出现缺价、单期最多占 12.5% 权重，累计收益跨度就有 **30pp**。
换个政策就换个结论。

无损移除会把退市前的亏损直接扔掉，全额清算会造出并未发生的暴跌。正确做法是
只在**权威退市日**挂损失 —— 工具无从得知那个日期，所以给你区间，
那就是这份净值的记账不确定性下界。

**但这个次序有前提。** 上面 `drop > hold_last` 成立是因为退市前有崩盘 ——
无损移除扔掉的是一段**真实亏损**。若标的在中性价位凭空消失（没有亏损可扔），
`drop` 就只是「在存活标的上重新归一」，高低取决于存活标的当期涨跌：
实测 6 个无崩盘面板里 **4 个出现 `drop < hold_last`**。

所以工具报**区间**，不报「哪种政策偏高」。`tests/test_core.py` 里两条断言分别
钉住这两种情形 —— 后者是反向断言，记录的是我原本搞错的事。

### 4. 负结果必须附最小可检出效应

干净组合（60 只池、10 只等权、无前视）上，「吃掉调仓日当天收益」能多赚：

```
每期 +0.116%（相对 +10.4%）   配对 t = 0.75
本样本最小可检出              0.301% /期
```

相对多 10% 看着像问题，其实连一倍标准误都不到。第一版工具只看比例、没有噪声
模型，于是在干净组合上报 WARN —— **会被客户关掉的告警等于没有告警**。

所以每个负结果都附 MDE：「没查出问题」和「查不出这么小的问题」是两回事。

## 真实面板端到端验证

上面四条是合成面板。工具真正的检验是在**真实 A 股面板**上跑
（800 只 / 2015-2026 / 2787 交易日 / 126 期月频），策略是 20 日反转、
市值加权、选 30 只 —— 同一个投资逻辑造两版，只有实现细节不同：

| | careless | careful |
|---|---|---|
| 信号时点 | 调仓日收盘（收市后才拿到） | 滞后一日 |
| 权重口径 | 调仓日市值（含当日收益） | 上一调仓日市值 |
| 股票池 | 样本末仍在册的名单 | 调仓日当时可见 |
| **毛年化** | **6.19%**（Sharpe 0.34） | **3.63%**（Sharpe 0.26） |
| 审计结论 | 1 项 BLOCK | 0 项 BLOCK |

三处漏口合起来把毛年化抬高 **2.56pp（+71%）**。逐个隔离：信号同日
+2.11pp、权重同日 cap +0.76pp、股票池生存者 +0.01pp。

**这一轮抓到工具自己两个实质缺陷**，都是合成面板测不出来的：

**① 停牌被误判成退市。** 真实面板上 24 个「持有但无价格」事件
**100% 都是停牌**（之后全部复牌），工具却全报成「记账政策决定结论」并给
BLOCK。合成面板里"消失"就是永久消失，所以测不出这个区别。现在会先分类，
全是停牌时说清楚「全额清算在停牌上是错的记账 —— 停牌股会复牌，不该记 −100%」。

**② 小而一致的前视被幅度门槛放过。** 把权重改成按**下期**市值加权
（教科书 vw 前视），毛年化从 3.63% 跳到 **13.85%**（近 4 倍），
而截面秩相关只有 **+0.088**，t=4.15。第一版要求 `|corr| ≥ 0.10` 才报警，
于是这个铁证判了 OK。30 只持仓上真前视就是「小而一致」——
**一致性才是证据，幅度只是效应量**。判据已改成看显著性。

复现：`python examples/real_ashare_e2e.py`（需自备面板，路径在脚本顶部）。
两条教训钉在 `tests/test_real_data_lessons.py`。

## 输入契约

**权重面板**（必需）

| 列 | 说明 |
|---|---|
| `date` | 调仓日 |
| `code` | 标的代码 |
| `weight` | 目标权重 |

**价格面板**（必需，与 [factor-audit](https://github.com/val1813/factor-audit) 同一契约）

| 列 | 说明 |
|---|---|
| `date` | 交易日 |
| `code` | 标的代码 |
| `close` | 收盘价（前复权） |

可选：`--net`（你算的净收益，用于毛净对账）、`--benchmark`（盈亏平衡按超额算）。

### 契约会 BLOCK 的三件事

**权重有空值** —— 不会替你 `fillna(0)`。空值有两种含义：「这期不持有」(=0) 与
「数据没取到」(未知)。当成 0 会把数据缺失记成主动清仓，而清仓在换手里是一笔
真实交易 —— 凭空造出成本，或凭空抹掉持仓。

**面板有重复行** —— `pivot` 会静默保留其中一行，而两行的值可能不同。
（实测真实面板出现过：某月两日共 11998 重复行。）

**权重和不为 1** —— 偏离超过 1% 时 BLOCK 而非静默归一。权重和 0.95 有两种可能：
有意留了 5% 现金（归一会抹掉现金拖累这个真实收益来源），或者权重算错了
（不归一则净值口径错）。工具不替你判断是哪一种。

## 与 factor-audit 的分工

| | 审什么 |
|---|---|
| [factor-audit](https://github.com/val1813/factor-audit) | **信号层**：检验做没做对（IC、NW t、独立簇 Bonferroni、衰减、集中度、六项面板体检） |
| strategy-audit | **组合层**：信号到净值这一段（换手成本、前视、成分记账） |

共用 `date/code/close` 价格面板契约，可以串起来用：

```python
from factor_audit import check_panel
from strategy_audit import audit_strategy

print(check_panel(prices).text())          # 先体检数据
print(audit_strategy(weights, prices).text())   # 再审组合
```

`strategy-audit` 的股票池生存者检查依赖价格面板本身含退市股。若面板是纯生存者
面板，它会说**「无法判定」**而不是 OK —— 先用 `factor-audit` 的面板体检确认数据。

## 报告怎么读

三级：

- **BLOCK** —— 净值不可信，先修这个
- **WARN** —— 可用，但按给出的量级打折
- **OK** —— 查过了，通过

外加**未能检查**一节。缺列、期数不足、数学上无定义都会列在这里，
写明「以上各项没有查过，不是查过通过了」。静默跳过等于让客户以为查过了。

跳过的理由必须**说对**。等权组合的权重没有截面变化，权重-收益相关系数在数学上
无定义 —— 那不是「持仓过少」。报错原因会让人去修一个不存在的问题，然后对
后续所有告警都不再相信。

CLI 退出码：有 BLOCK 返回 1，方便进 CI。**WARN 不算失败** —— 让 WARN 挂 CI
会逼客户去关告警。

## 三件它不做的事

- **不告诉你策略好不好** —— 判「能不能上」需要你的收益预期和执行现实
- **不替你选成本假设** —— 主输出是盈亏平衡成本，那不需要任何假设：
  「你的策略需要单边成本低于 X bp 才有正超额」。X 很小就是坏消息，
  不管你的真实费率是多少
- **不上传任何东西** —— 全本地运行，持仓不出你的进程

## 数据由你提供

不内置数据源，也不分发行情（版权）。与 factor-audit 同一条原则：实测免费源
会拉黑 IP、非线程安全、对退市股返回「空 + success」—— 把它们做成依赖，
等于把它们的失败变成本工具的失败，而客户会认为是我们坏了。

## 核心数学是可对账的

`period_returns()`（按区间一次算清）和 `daily_path()`（按日复利、权重随价格漂移）
是两条独立实现，区间内买入持有时数学上恒等。测试断言两者偏差 **< 1e-12**
（实测 4.5e-16）。

漂移权重极易写错，而写错之后净值仍然「看起来合理」。只有对账能抓到 ——
闸门自己也会标定错，所以不测「结果看起来对」，只测两条独立实现是否恒等、
已知答案能否精确反推（植入 15bp 费率，对账必须反推出 15bp）。
